# K-Tour ID · 지도 읽기와 장소 액션 개선

작업 브랜치: `integration/harvey-preservation-20260924`.
범위: **로컬 UX 수정·검수**. 원격 push, 공개 배포, 신규 실환경 인증·결제·체인 거래는 하지 않는다.

## 1. 지도에서 콘텐츠를 읽고 장소로 이어가기

```text
도시 지도 → 이야기 → 짧은 소개 → [선택] 본문 펼치기
 → 글 속 장소 → 기존 장소 상세 → 뒤로 → 같은 이야기·선택 장소·읽기 위치
```

- 서울 중부시장 참기름 이야기, 제주 두 촬영지 이야기의 KO/EN/JA 소개·본문·장소별 설명을 추가했다. 이미지·원문·좌표·기존 장소 ID는 보존한다.
- 서울 내용은 [루루부의 중부시장 소개](https://rurubu.jp/andmore/article/25110), 제주 장소와 작품 연결은 [VISITKOREA](https://japanese.visitkorea.or.kr/svc/contents/contentsView.do?vcontsId=222180)를 기준으로 편집했다. 원문 전체 복제, 개별 매장 영업·실시간 혼잡·특정 촬영 장면의 추가 주장은 하지 않는다.
- 기본 지도 하단에 이야기·Hot·Cool·목록을 한 줄로 모았다. 콘텐츠를 열면 목록 전환은 해당 패널 하단에 있다. 큰 © 버튼은 없애되 지도 출처 링크는 화면에 유지한다.
- 좁고 짧은 화면의 접힌 이야기에서는 소개를 한 줄 발췌로 보여주며, 펼치면 소개·본문 전체를 읽을 수 있다. 이전/다음 장소 버튼은 ‘이야기 펼치기’ 옆에 모아 지도 핀과 선택 장소 카드가 하단 도구에 가려지지 않게 했다.
- Hot/Cool은 **고정 편집 추천**이다. 기존 도시·카테고리·After 19 조건을 무시하거나 다른 도시로 이동해 추천 수를 채우지 않는다. 도시 미지원과 필터 결과 없음은 다른 회복 안내를 제공한다.
- 읽기 위치는 `sessionStorage`의 `ktour-story-reading:{collection}`에 `expanded/top`만 보관한다. 신원·승인·결제·체인 상태가 아니다. 장소 창의 열림/닫힘으로 배경 높이가 바뀌는 동안에는 이 위치를 덮어쓰지 않는다. 복원은 최대 500ms이며 새로운 사용자 입력이 우선한다.
- 제주 무점수 편집 장소에 숫자 없는 온도계를 장식으로 표시하지 않는다. 촬영지·편집 추천이라는 중립적 의미를 표시하고 출처 상세는 유지한다.
- 데모 여정 진입은 `옵션 → 데모 → 체험 혜택 여정 시작`으로 옮겼다. 기존 지정 장소·혜택 동의·실행 경로를 재사용하며 자동 인증·서명을 추가하지 않는다.

## 2. 결제·충전 화면

```text
장소 결제 확인 → 잔액 부족 → 충전 수단·금액 선택 → 별도 전송 승인
 → 출발·도착 확인 → 잔액 반영 → 같은 장소·주문 복귀 → 별도 결제 동의
```

- 사용 가능 잔액과 부족액을 같은 요약 영역에 표시한다. 부족한 상태를 `잔액 → 0원`처럼 차감 완료로 오해할 수 있게 표현하지 않는다.
- ‘이 결제를 위해 충전’ 주 버튼은 기존 충전 진입(`purpose: topup`)을 연다. 이전의 결제 수단 선택 진입과 문구가 불일치하던 부분을 바로잡고 중복 충전 버튼은 제거했다.
- 부족액과 선택 충전액은 별개다. 예: 부족 24,000원이어도 선택한 충전 견적 30,000원은 그대로다.
- `settled && creditComplete`인 경우에만 완료 금액·잔액·복귀 버튼을 먼저 보여준다. 경로·영수증은 펼쳐 확인할 수 있다. 도착 확인만 끝나고 잔액 저장이 실패한 경우는 완료로 바꾸지 않는다.
- 같은 주문·고정 견적·매장에 복귀하며, 충전 승인을 결제 동의로 재사용하지 않는다. 고정 헤더에 매장과 결제 예정 금액을 남긴다.
- 상태 모델·SDK·견적 산정·동의 함수는 변경하지 않는다. 전송 전 금액·자산·네트워크·수수료·유효시간과 승인은 계속 표시한다.

## 3. 장소 상세의 정보 구분

- 결제·매장 예약·체험 혜택은 장소 액션으로 묶고, 무료 가이드와 방문 스탬프는 ‘가이드·여행 기록’ 구역으로 나눴다. 각 버튼의 기능·상태·인증 조건은 독립이다.
- 식사 모임은 ‘여행자와 함께 먹기’로 표시해 ‘매장 예약’과 구분한다. 지난 모임 안내, 열람 진입, 19+ 참여 조건은 그대로다.
- canonical 상세에서만 가이드를 별도 구역으로 옮긴다. 다른 장소 상세·peek 진입의 기존 액션 배치는 유지한다.
- 복귀 대상·포커스·스크롤 속성은 기존 leaf 액션에 남긴다. 구역 전체를 공통 인증·결제 대상으로 만들지 않는다. 지원하지 않는 서비스 구역은 빈 카드로 표시하지 않는다.
- desktop에서도 구역의 시각 순서를 DOM/탭 순서에 맞췄다. 무료 읽기에 로그인이나 패스 저장을 요구하지 않는다.
- 서비스가 없는 desktop 장소는 장소 소개 옆에 온도와 여행 기록을 이어 배치해 비어 있는 서비스 구역의 여백을 남기지 않는다.

## 개발자에게 달라지는 점

- 이번 개선에 따른 신규 서버 endpoint, VC/VP schema, Move/OmniOne 계약, provider 환경변수 요구는 없다.
- Harvey 혜택 사용 v1, 무료 가이드·선택 저장 v2 목업, 금융·예약 목업은 계속 독립이다. 어느 한 흐름의 성공을 다른 흐름의 자격·동의로 쓰지 않는다.
- 실제 환경의 시작점과 미완료 조건은 [Harvey 보존 통합 보고서](./HARVEY_PRESERVATION_INTEGRATION_2026-09-24.md)를 따른다. OpenDID native holder 및 실환경 E2E가 이번 UX 작업으로 완료되는 것은 아니다.
- full-stack 배포와 map-only standalone 배포의 차이를 유지한다. standalone의 해커톤 slot은 비활성 stub이며 SDK/API를 끌어오지 않는다.
