# 모바일 타이포·여백 검수 — 2026-09-25

> 이 문서는 수정 전 검수 기록이다. 이후 사용자 승인으로 N1–N3를 로컬 구현했다. 현재 변경·재검수 결과는 [모바일 타이포 반영 기록](./KTOUR_MOBILE_TYPOGRAPHY_IMPLEMENTATION_2026-09-25.md)을 참고한다.

대상: `integration/harvey-preservation-20260924`의 로컬 고정 빌드 `http://127.0.0.1:3140`. **검수만 수행하며 앱 코드·스타일·데이터 모델·배포는 변경하지 않는다.**

사용자가 선택한 기준은 설정 화면의 제목과 여백이다. 같은 등급의 일반 페이지 제목은 이 기준으로 정렬하되, 지도 조작부·바텀시트·카드 내부에 페이지 제목 규칙을 일괄 적용하지 않는다.

## 판단 방법

세 리뷰를 독립적으로 진행한 뒤 측정값과 반론을 교차 검토한다.

1. 시각 위계·실측: 5개 주요 탭, 제목·섹션·설정 하위 화면.
2. 반응형·다국어: 320/390px, 한국어/영어/일본어, 줄바꿈·버튼 영역·확대 스트레스.
3. CSS·플로우 맥락: 최종 적용 스타일, 패스/지갑의 동급 객체 가능성, 페이지와 시트의 차이.

기준은 [기존 내부 UX 지침 §4.2](./toss-grade-ux/00_UX_STANDARD.md): 화면 제목 28–32px/1.08, 섹션 20–22px/1.2, 본문 15–17px/1.45, 작은 화면 좌우 16px·390px 좌우 20px, 조작 영역 최소 44px. 이는 제품 내부의 일관성 기준이지 모든 제품에 적용되는 법칙이나 접근성 인증 판정이 아니다. 최신 승인된 지도 헤더는 별도 예외다.

수치는 스크린샷의 이미지 픽셀이 아닌 **브라우저 CSS px**다. 스크롤을 맨 위로 놓고 실제 computed style과 DOM 사각형을 측정했다. 제목 영역의 사각형은 글자 잉크 경계가 아닌 line box이며, 컨테이너 상단·행 높이·다음 콘텐츠 간격과 구분한다. 이번 브라우저의 safe-area inset은 0이며 실제 기기의 노치·주소창 조건을 대신하지 않는다.

## 핵심 실측

390px 일본어, 일반 표시 크기 기준. 소수점은 반올림했다.

| 화면/요소 | 제목 크기 / 줄높이 | 제목 line box의 위쪽 좌표 | 확인 사항 |
|---|---:|---:|---|
| 설정 | 32 / 33.3px | 35.4px | 헤더 프레임 상단 28px, 최소 높이 48px, 다음 목록까지 24px |
| 여행 패스 | 33.9 / 32.9px | 19.5px | 헤더 프레임 상단 14px, 높이 44px, 다음 패스 카드까지 8px |
| 내 한국 | 31.2 / 31.2px | 24px | 제목에서 실제 미니 지도 카드까지 14px |
| 테이블 | 39 / 39.8px | 23px | 320px에서는 32 / 32.6px; 카드 제목도 22.4→27px로 커짐 |
| 지갑 섹션 | 35.1 / 52.7px | 스크롤 콘텐츠 내부 | 줄높이 1.5를 상속, 다음 잔액 카드까지 약 10px |
| 지도 헤더 | 19 / 25.7px | 29.2px | 조작용 compact header이므로 일반 페이지 제목과 직접 통일하지 않음 |

320px에서는 설정 제목 30px, 좌우 16px, 헤더와 목록 사이 18px다. 여행 패스는 상단 14px·카드 앞 8px가 유지된다. 따라서 사용자가 지적한 여행 패스의 압축된 배치는 실제 스타일 차이로 재현된다.

## 최종 합의: 3개 개선 항목

| 항목 | 실측·위계 리뷰 | 반응형·다국어 리뷰 | CSS·맥락 리뷰 | 판정 |
|---|---|---|---|---|
| N1 일반 페이지 제목 프레임 | 동의 | 동의 | 동의 | 3/3. 콘텐츠별 간격 변형은 보존 |
| N2 테이블의 글자 확대 폭 | 동의 | 동의 | 동의 | 3/3. 내부 스케일 일관성 개선 |
| N3 지갑 제목 줄높이 명시 | 동의 | 동의 | 동의 | 3/3. 지갑 제목 크기 강제 축소는 제외 |

초기 의견을 억지로 하나로 맞추지 않았다. ‘패스 카드를 반드시 설정 목록과 같은 간격으로 배치’, ‘지갑 h2는 반드시 패스 h1보다 작게’에는 조건부 의견 또는 반대가 있었다. 그 요구는 확정안에서 제외하고, 위처럼 공통 프레임·콘텐츠별 변형·명시적인 줄높이로 범위를 좁힌 후 재검토해 합의했다. 3명 합의는 사용성 실험이나 모든 미감의 객관적 증명을 의미하지 않는다.

### N1. 일반 페이지 제목 프레임 통일

- 대상: 여행 패스, 내 한국, 테이블. 설정은 기준 화면.
- 문제: 같은 루트 탭 제목인데 시작 위치·행 높이·글자 스케일의 규칙이 서로 다르다. 여행 패스는 상단과 첫 카드 간격이 특히 압축돼 있다.
- 방향: 설정을 기준으로 공통 제목 프레임을 정의한다. 상단 28px, 제목 약 30–32px, 좌우 16/20px를 출발점으로 삼는다. 정확한 값은 후속 구현 시 시각 검수로 확정한다.
- 예외: 패스 카드 내부 밀도, 내 한국의 지도, 테이블의 미디어 등 **첫 콘텐츠의 간격은 명시적인 변형으로 유지**할 수 있다. 모든 화면에 똑같은 흰 여백을 강제하지 않는다. 긴 제목과 텍스트 확대 시 보조 버튼이 다음 줄로 이동할 수 있어야 한다.
- 관련: `settings/settings-entry-b.module.css:1`, `identity-b/traveler-id-entry-b.module.css:319`, `shared/ui/production-local.module.css:265`, `connect/pulse-table-b.module.css:1048`.

### N2. 테이블의 모바일 글자 확대 폭 제한

- 문제: 화면 폭이 320→390px로 바뀔 때 루트 제목 32→39px, 카드 제목 22.4→27px로 커진다. 내부 제목 스케일과 다른 탭에 비해 강조가 강하다.
- 방향: 루트 제목은 공통 28–32px 범위, 카드 제목은 20–22px 범위를 기준으로 정리한다. 두 줄 제목은 자연스럽게 줄바꿈하고 행동·금액·시간을 가리지 않아야 한다.
- 분류: **일관성 개선**. 현재 기본 크기에서 잘리는 버그나 breakpoint의 불연속 오류가 아니다. `vw` 기반의 연속적인 확대다.
- 관련: `connect/pulse-table-b.module.css:1057` 및 카드 제목의 모바일 규칙.

### N3. 지갑 제목의 줄높이를 명시

- 문제: 지갑 제목은 35.1px 글자에 52.7px 줄높이(1.5)를 상속한다. 같은 탭의 패스 제목은 약 0.97이다. 제목끼리 서로 다른 행 리듬을 사용한다.
- 방향: 제목용 줄높이와 다음 카드까지의 간격을 각각 명시한다. 글자 크기와 행간을 한꺼번에 줄여 카드가 더 붙어 보이지 않도록 검수한다.
- 반론 수용: 패스와 지갑은 `ID · 지갑` 탭 안에서 동급의 큰 객체일 수 있다. **h2가 h1보다 크다는 이유만으로 지갑 제목을 무조건 작은 섹션 제목으로 낮추지는 않는다.**
- 관련: `commerce-b/id-wallet-commerce-b.module.css:590`, `:1066`.

## 유지할 부분 / 확정 문제에서 제외

- 지도 헤더의 19px 제목과 작은 조작부: 승인된 지도 중심 구성에 맞는 의도적 차이.
- 바텀시트의 작은 중앙 제목: 페이지 제목과 다른 역할. 설정의 큰 제목·상단 여백을 그대로 복사하지 않는다.
- 설정 화면 하단의 빈 공간: 항목이 적어서 생긴 결과이며, 그 자체를 결함으로 보지 않는다.
- 기본 표시 크기에서 확인된 5개 탭: 가로 넘침·제목 잘림은 재현되지 않았다. 이번 주된 지적은 일관성과 밀도다.
- 작은 메타데이터를 전부 본문 크기로 키우거나, 카드 종류마다 무조건 같은 제목 크기를 강제하는 변경은 합의 대상이 아니다.

## 별도 스트레스 관찰 — 기본 상태 결함과 구분

320px 영어 설정에서 각 텍스트의 계산된 글자 크기를 2배로 만드는 브라우저 내 실험 시, Demo 버튼의 오른쪽 끝이 약 345.7px까지 나가 잘렸다. 설정 헤더를 재사용한다면 긴 문구·확대에 견디는 줄바꿈 처리는 함께 검토해야 한다.

이는 **CSS 글자 확대 시뮬레이션**이다. 실제 iOS Dynamic Type, Safari의 글자 확대, WCAG 적합성 검사를 수행했다는 뜻이 아니다. 기본 크기의 잘림이나 세 리뷰 모두가 실제 기기에서 재현한 결함으로 계산하지 않는다.

## 검수 범위와 증거

현재 완료된 기본 매트릭스: 실제 앱 5개 탭 × 320/390px × KO/EN/JA. 같은 화면을 서로 다른 리뷰가 독립 확인한 횟수는 별도 페이지 수로 중복 계산하지 않는다.

- 리뷰 1: 주요 탭 30상태, 일본어 320px 설정의 언어·표시 모드·취향·개인정보 시트. 측정 `/tmp/ktour-mobile-type-review.json`.
- 리뷰 2: 주요 탭 30상태, 취향·지갑 연결 안내·테이블 상세·내 한국 프로필 24상태, 글자 확대 시뮬레이션 8상태. 화면 `/tmp/ktour-spacing-r2-*.png`.
- 리뷰 3: 주요 탭 실측 및 설정·장소·가이드·예약·온보딩·stablecoin funding의 소스 구조 확인. 소스 검토만 한 화면은 실제 렌더 검수와 구분한다.

추가 완료:

- 일본어 다크 모드: 5개 탭 × 320/390px, 지갑 스크롤 화면 2개. 라이트와 같은 geometry이며 새로운 다크 전용 잘림은 관찰되지 않았다. `/tmp/ktour-spacing-dark-{320,390}-ja-{ondo,my,tables,id,settings,wallet}.png`. 명암비 인증 검사는 아니다.
- K-Tour ID 확인 방법 선택 시트: 일본어 320/390px에서 직접 진입. 제목/본문/44px 이상 컨트롤의 잘림·겹침 없음. `/tmp/ktour-id-setup-ja-{320,390}.png`.

남은 범위 — 전수 렌더 검수 완료로 표기하지 않음:

- 격리 guest 상태에서 지갑 충전 진입이 없고 스탬프 상세도 수동 진입 가능한 상태를 확보하지 못했다. 공급자/인증/거래를 제출해서 억지로 상태를 만들지 않았다. 충전·영수증·스탬프 상세의 모든 상태를 본 것은 아니다.
- 장소 상세·방문·가이드·예약·온보딩은 관련 CSS/구조를 검토했다. 이번 후속 브라우저 시도에서는 스토리 진입 조작을 완료하지 못해 신뢰할 수 있는 추가 캡처를 얻지 못했다. 이를 제품 결함으로 단정하거나 해당 하위 화면의 런타임 검수 통과로 계산하지 않는다.
- 따라서 이번 결과는 **주요 5개 탭의 전체 모바일 제목 비교 + 접근 가능한 하위 화면 + 나머지 흐름의 소스 검토**다. 모든 사용자 상태 조합의 완전한 UI 전수 검수는 아니다.

외부 제공자 화면, 실제 신분증/서명/결제 제출, 실기기 키보드·노치, 모든 실패·만료·완료 조합은 이번 타이포 검수 범위 밖이다. Chromium 모바일 viewport 검수이며 실제 iPhone/Safari 전수 검수는 아니다.
