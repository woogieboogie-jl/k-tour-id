# K-Tour ID · 모바일 화면별 개선 정의

2026-09-16 · **모바일 1차 검수 및 개선 정의 — 진단 당시 기록** · 로컬 전용

후속 상태: 사용자 승인 후 아래 **M01–M13 + R1–R9, 22개 항목을 하나씩 로컬 구현 → 독립 반대 검토 → 회귀 검사**했다. 최종 고정 빌드 결과와 미검수 한계는 [현재 로컬 인계](../../KTOUR_MOBILE_REFINEMENT_LOCAL_2026-09-16.md), 항목별 근거는 [구현 로그](./IMPLEMENTATION_LOG.md)를 따른다. 아래 관찰은 수정 전 진단이며, 과거 결함을 현재 상태로 읽거나 모든 기기·상태의 합격으로 확대하지 않는다. commit/push/배포는 하지 않았다.

## 이번 검수의 기준

전체 진입점과 단계부터 코드로 대조한 뒤, 디자이너 역할 에이전트 3명이 탐색 / 개인·소셜 / 신원·거래를 나눠 실제 로컬 화면을 확인했다. 코디네이터는 공통 시트와 영역 사이의 연결을 별도로 확인한다. 실제 사람 디자이너 3명의 외부 심사를 뜻하지 않는다.

- 기준: 기존 `00_UX_STANDARD.md`, PRD 보존 대장, 9/15 visual standard, 최신 Journey–Pass 변경 정의.
- 모바일 기준 폭 390px, 좁은 화면 320px 및 KO/EN/JA·다크·짧은 높이 스트레스. 모든 화면과 모든 언어·상태의 조합을 완주했다는 뜻은 아니다.
- 83개 의미 단위는 페이지/URL 수가 아니다. 5개 내부 탭, 시트, 내부 단계, 공통 셸, 실연동 경계를 합친 검수 분모다. 실제 관찰/코드만 확인/범위 밖을 [coverage](./coverage.md)에서 구별한다.
- 기존 테스트 통과나 예전 스크린샷을 이번 시각 검수의 통과 증거로 재사용하지 않는다. 현재 로컬 artifact의 화면과 계산된 스타일을 함께 기록했다.
- **진행을 막는 결함 → 중요한 내용의 가독성 → 페이지 간 일관성 → 미감 디테일** 순서로 판단한다. 작은 출처/시간 라벨과 결제·동의 본문을 같은 기준으로 무조건 확대하지 않는다.

## 고치더라도 보존할 것

지도부터 탐색하는 첫 진입, 선택형 온보딩, 장소로 정확히 복귀하는 흐름을 유지한다. Account / Person / 19+ / Payment / K-Tour ID는 하나의 ‘인증 완료’로 합치지 않는다. 읽기에는 신원 확인을 강제하지 않는다. 충전·결제·환불의 승인과 불확실한 결과 조회를 없애지 않는다. 결제가 방문 스탬프를 만들지 않고, 10곳 기념품도 선택이다. Tables의 식사 계획과 매장 예약은 서로 다른 기능이다.

동의의 요청자·목적·최소 공개 항목·보관 범위, 금액·수수료·자산/네트워크·실행 결과는 미감을 위해 감추지 않는다. 긴 기술 설명만 상세로 이동한다. 샘플 결과를 실제 확인·금전 이동으로 바꾸어 표현하지 않는다.

Table 참여 결정의 ‘로컬 식사 계획일 뿐, 매장 예약이 전송되지 않음’이라는13px 설명도 M06–08과 같은 **결과 의미의 가독성** 기준으로 개선한다. 반면 현재 온전히 읽히는 시간·인원·비용의12px 값은 아래 P2 시각 정리에서14–15px로 다듬는다.

M10의 하단 버튼은 정상 스크롤로 접근 가능했다. ‘첫 화면 아래에 있음’을 클릭 불가 결함으로 분류하지 않는다. 200% CSS zoom 진단에서의 결제 금액 잘림은 별도 스트레스 후보이며, 실제 브라우저 확대/텍스트 확대 검증 전 접근성 실패로 단정하지 않는다.

### 미감 방향 · 기능을 지우지 않고 정리하기

검정 주 버튼, 중립적인 카드·배경, 데이터에만 사용하는 온도 색상을 공통 문법으로 삼는다. 기본 글꼴·제목 단계·20px 본문선·24/32px 섹션 간격을 먼저 정렬한다. 페이지마다 새 장식 카드와 그림자를 더하는 대신, 같은 역할에는 같은 구성 요소를 쓴다.

특히 Table 상세는 ‘시간·장소·인원·비용 → 참여’가 중심이다. 현재 전체 폭으로 먼저 나오는 장소 복귀/매장 예약은 보조 액션군으로 정리하고, 선택형 프로필이 참여 판단을 가로막지 않게 위치를 조정한다. 예약·프로필·안전 기능 자체를 삭제하지 않는다. 사실 목록의 장식용 컬러 세로선은 실제 단계나 온도 데이터가 아니므로 의미 있는 정보처럼 보이지 않게 정리한다.

## 교차 검토 결론

세 역할의 검수자가 자기 영역 밖의 근거도 열어 반대 검토했다. Directions/다크 대비/잘못된 일정/신고 줄바꿈/화면 밖 확인 창은 결함으로 합의했다. Partner 동의 맥락과 일반 방문 기록의 상충 상태도 보완 대상으로 합의했다.

처음에는 제목 크기·13px 바깥 여백·영수증 하단 버튼·Table의12px 사실 라벨까지 넓게 ‘필수’로 묶는 제안이 있었지만, 실제 접근 가능성과 정보 성격을 대조해 조정했다. **중요한 동의·결과 문장은 개선하고, 단순 메타데이터는 무조건 확대하지 않으며, 정상 스크롤은 가림 버그가 아니다.** 충전의 주 버튼 경쟁과 영수증 제목은 P2로 내려 기능 결함과 구분했다. 기준은 다수결 취향이 아니라 관찰 근거와 PRD 보존이다.

## 적용 순서와 회귀 검사

1. **진행/정확성:** M01 → M02–05, M12. 레이어·컨트롤·테마·동일 객체의 시간부터 수정.
2. **결정 가독성:** M06–08과 Journey 초기화 안내. 공통 본문/동의/상태 컴포넌트부터 적용하고 페이지별 과밀을 조정.
3. **시각 통일:** M09–10 및 온보딩·footer·상세·Table 우선순위. 새로운 장식보다 공통 기준선을 맞춤.
4. **운영자:** M11. 시연에서 신원 공유의 맥락이 빠지지 않게 정리.
5. 변경 작성자 외 검수자가 EN/KO/JA,320/390/430,light/dark, 실제 좌표 탭·스크롤·취소/복귀를 다시 확인. 중요한 곳은 픽셀/대비/문구·동일 시간 검사를 회귀 테스트로 남김.

추가 확인이 필요한 정책 한 가지: After19가 현재 승인된 야간 subset만 보여주는 동작과 오래된 PRD의 ‘일반 야간 음식점 유지’ 문구가 다르다. 이번에는 정책을 임의 변경하지 않는다. 해당 필터를 바꾸는 단계에서 범위를 확정한다.

실제 기기 키보드/Safari, native 텍스트 확대, 갱신·복구/만료·저장소 실패의 전 조합은 별도 회귀 항목이다. 이것들이 검수되지 않았다는 이유로 기능을 삭제하지 않으며, 반대로 전체 완주했다고 주장하지 않는다.

## 이미 로컬에서 수정한 공통 결함

`Your visit` 시트의 둥근 모서리 바깥으로 옅은 사각 배경이 보이던 현상은 재현했다. 부모는 둥글지만 헤더의 별도 blur 합성 표면이 사각형으로 그려지는 문제였다. 헤더·푸터가 해당 모서리 radius와 동일한 불투명 표면을 직접 갖도록 정리했다. 시트 전체를 마스킹하여 그림자나 포커스 링을 자르지 않았다.

- 수정 전 실제 픽셀 검사 실패(820px light, 배경 대비 차이 188; 허용 12).
- 수정 후 320/390/820/1440px × light/dark **8개 픽셀 검사 통과**. 프로젝트 불일치로 생략된 8개는 통과 수에 넣지 않는다.
- 관련 계약 6개, 타입 검사, 로컬 빌드 통과.
- 다른 자체 제작 시트는 같은 CSS 위험이 있어도 별도 재현 전까지 ‘고쳐졌다/깨졌다’고 단정하지 않는다.
