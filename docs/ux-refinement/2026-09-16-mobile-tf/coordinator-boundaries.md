## 판단

### 반드시 보완: Partner의 결과 공유 동의에 요청 맥락 추가

`partner-008-holder-consent.png`에는 “Your choice / 19+ / Only this result is shared / Share result”만 보인다. 19+라는 공유 항목은 알 수 있지만 **누가 무엇을 위해 요청했고 얼마 동안 유효한지** 승인 화면만 읽어서 판단하기 어렵다. 소비자 주 경로가 아닌 운영자 샘플 도구라는 점에서 빈도는 낮지만, 최소 공개 동의의 맥락은 보존해야 한다.

수정 정의: 기존 샘플 요청자 `Sample café counter`, 목적, 공유되는 yes/no 결과, 실제 구현에 맞는 보관 범위, 요청 만료를 한 개의 읽기 쉬운 정보군으로 표시한다. 요청자 이름을 실매장으로 꾸미거나 존재하지 않는 보관 정책을 쓰지 않는다. deny/샘플 경계는 남기고 audience/domain/nonce 같은 기술값만 펼침 상세로 보낸다. 잘못된 대상·재사용·만료 검증을 시각 개선을 이유로 제거하지 않는다. Designer3가 화면과 소스를 교차 검토해 이 방향에 동의했다.

### 개선 권장: 가이드 읽기/저장 화면의 본문과 중첩 여백

주요 가이드 문단이13px이며 카드 바깥과 안쪽, 공통 footer에 여백 소유자가 겹쳐 있다. 읽기 본문은15–16px로, footer는 공통16/20px 기준선으로 정렬한다. 저장 승인 화면의 동의가 첫 화면 아래로 내려가는 것은 내부 스크롤이 있으므로 곧바로 가림 버그가 아니다. 불필요한 반복 제목/아이콘 공간을 줄이면 결정 항목이 더 빨리 드러난다.

처음 저장할 때 계정/Person/패스 수령/제시/실행 동의가 이어지는 경로는 해커톤 계약상의 서로 다른 결정이다. 단지 길다는 이유로 합치거나 자동 승인하지 않는다. 이미 충족된 조건 재사용과 같은 대상 이름·진행 목적·취소 복귀의 일관성으로 부담을 줄인다. 무료 읽기는 그대로 둔다. 현재 이 가이드는 review 화면에서 제공되며 정상 provider 모드의 상용 서비스 제공을 뜻하지 않는다.
