# 메인 플로우 통합 — 구현·실연동 구분

기준: 2026-09-29. 이 문서는 구현 완료와 실제 제공자 검증을 구분한다.
이번 배포는 기존 운영 CX/Sui 프로필을 유지하며, 준비되지 않은 새 권한을 활성화하지 않는다.

## 사용자가 확인할 경로

- 운영: https://ktour-id.vercel.app/?city=seoul&review=0
- 로바 장소 상세 → 골목 가이드: 인증 없이 읽기 → 선택적으로 패스에 담기.
- Travel Pass → 내 골목 가이드: 같은 가이드 화면을 공유한다.
- 연결 미준비 상태에서는 저장 불가를 안내하고 계속 읽기로 돌아간다. 가짜 저장 성공이나 과거 체험 혜택으로 대체하지 않는다.
- 기존 모바일 신분증 체험 혜택은 별도 기존 경로로 유지한다. 새 가이드 저장과 같은 권한이라고 주장하지 않는다.

## 이번 후속 작업에서 더 완료한 것

- 메인 가이드 전용 빌드·서버 접근 프로필을 구현했다. 별도 HttpOnly 쿠키와 정확한 경로/본문/출처 검증을 사용하며 기존 체험 혜택·Preview 쿠키와 섞이지 않는다. **기존 운영 프로필을 이 프로필로 전환한 것은 아니다.**
- 클라이언트는 서버가 알려 준 접근 프로필만 사용한다. 만료 시 같은 operation을 복구하며 새 요청·승인·서명을 자동으로 만들지 않는다.
- Sui의 준비·발급·사용자 제출·대리 실행을 operation 소유권과 연결했다. 서명과 방송 직전에는 실제 커밋된 원장을 다시 확인해야 한다. JSON 파일이나 환경 flag는 이 권한을 만들 수 없다.
- CX→Native→제안→사용자 승인→Sui→Pass→체인 기록의 실제 서버 오케스트레이션을 합성 제공자 경계로 검증했다. 실제 제공자 계약이 없는 부분은 테스트 프로세스에만 주입하며 운영에서는 계속 차단한다.
- 새 guide 빌드의 예전 체험 CTA·저장된 재개 정보·이벤트·단축 URL이 v1 경로를 열지 못하게 했다. 기존 hosted 운영에서는 기존 CTA가 유지된다.
- 실제 접근 쿠키·세션·API→서비스→원장→보관함을 V1 8개, 공유 예산 V2 10개 시나리오로 검증했다. 원장 권한 거절이 일반 재시도 오류로 바뀌던 응답도 수정했다.
- 기존 흐름의 중단/배포 삭제 없이 동일한 10회 한도를 공유하는 프로토콜을 추가했다. 빈 대상 원장 준비는 슬롯을 소비하지 않으며, 새 요청만 기존 원장에 회수 불가 예약을 남긴다.
- 제공된 Omni RPC를 기존 숨김 입력 도구로 소유자 전용 로컬 파일에 보관했다. URL 재전달을 사용자 업무로 남기지 않는다. recorder 키는 별도 미입력이다.
- 새 guide 내부 검수 배포는 공개 설정만 사용하고 runtime은 OFF다. 전용 빌드 manifest와 고정 Preview 배포 도구를 준비했으며 운영 설정·서명키·원장은 변경하지 않는다.

## 검증과 안전장치

- 재검토 후 TypeScript 단위 테스트 **625/625**, JavaScript 테스트 **165/165** 통과. 별도 자식 프로세스는 합성 오케스트레이션 **25개**, 인증된 실제 API 라우트 **18개**를 추가 검증한다.
- 검증 스위트 **70/70**, TypeScript 검사, 가이드 전용 비활성 빌드 및 기존 운영 프로필 빌드 통과. 배포 결과는 release receipt에서 확인한다.
- 이전 일본어 UI 모바일·데스크톱·320px fixture 계약 **42/42**에 이어 실제 guide 비활성 빌드 모바일/데스크톱 **6/6**을 검증하고 스크린샷을 직접 확인했다. 실제 배포의 읽기 전용 검수는 release receipt에 별도로 기록한다. 제공자 쓰기 성공 증거가 아니다.
- 독립 리뷰에서 중복 저장 전 체인 비용 발생, 취소 후 늦은 응답, provider 상태의 mock 우회, 잘못된 요청 본문, 출처가 다른 signer 복원 경로를 확인하고 방어했다.
- CX, Native, Google, Sui, OmniOne Chain에 이번 UI 검수용 쓰기를 보내지 않았다. 실제 본인 동의나 지갑 서명을 자동화하지 않았다.
- 기존 횟수/가스 원장을 초기화하지 않았으며, 실행 기한은 2026-09-30 23:59:59 KST 그대로다.
- 배포 검증은 같은 소스 SHA의 내부 Preview를 먼저 확인한 후 운영에 반영한다. 사용자에게 Preview에서 본인 인증을 요청하지 않는다.

## 남은 작업의 담당

사용자가 직접 할 단계는 [별도 체크리스트](OWNER_ONLY_NEXT_STEPS_2026-09-29.md)에 모았다. 키 값은 문서·채팅·Git에 넣지 않고 숨김 입력 도구로 로컬 소유자 전용 파일에 보관한다.
