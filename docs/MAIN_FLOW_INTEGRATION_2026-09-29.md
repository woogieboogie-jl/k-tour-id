# 메인 사용자 흐름에 기술을 배치하는 기준

상태: 구현 및 로컬 통합·독립 리뷰 완료 후 릴리스 검수 단계. 이 문서만으로 운영 반영이나 실제 제공자 성공을 주장하지 않습니다. 배포 SHA와 익명 운영 검수 결과는 별도 릴리스 기록에서 확정합니다.

## 사용자 입장에서

`콘텐츠 / 지도 / 검색 → 같은 장소 상세 → 원하는 행동 → 필요한 경우에만 본인 확인 → 원래 행동으로 복귀`

콘텐츠는 장소 위에 얹히는 추천 이유·출처입니다. 별도 상점 상세나 별도 결제 서비스가 아닙니다.
조사 장소의 실제 ID와 공인 지도 장소의 ID는 구분하며, 서로 다른 가게를 임의로 같은 상점으로 합치지 않습니다.

| 사용자가 하려는 일 | 인증 배치 | 해결하려는 문제 / 하지 않는 주장 |
| --- | --- | --- |
| 지도 탐색, 가이드 읽기, 장소 저장, 개인 여행 메모 | CX 불필요 | 탐색에 가입·신분증 장벽을 만들지 않음. 개인 방문 메모는 자가 기록이지 방문 증명·가맹점 확인이 아님 |
| Travel Pass에서 본인 확인 상태 준비 | 명시적 동의 후 공통 CX 확인 | 실제 모바일 신분증 제공 결과를 현재 세션의 서버 증거에 결합. 이것만으로 OpenDID 패스 발급이나 결제 KYC가 되지 않음 |
| 본인 확인이 필요한 장소 기록 작성 | 해당 장소·작성 중인 행동에 결속된 동의/인증, 마지막 제출 경계에서 서버 승인 소비 | 다른 장소, 다른 작성 내용, 만료·취소된 인증을 재사용하지 않음. 신원 확인은 내용이나 방문 사실의 진실성을 보증하지 않음 |
| 모임 참여 요청 | 해당 모임의 실제 정책에 필요한 축만 확인 | 본인 확인과 연령 조건을 분리. 현재 CX AdultVerify 결과만으로 정확한 19+ 정책 충족을 만들지 않음. 참여 요청은 운영자 승인·예약 확정이 아님 |
| After19 지도 보기 | 기존 개인 표시 설정/자가 선언 | 야간 지도 탐색 설정일 뿐, 성인 증명이나 제한 서비스 이용 권한이 아님 |
| 지정된 장소의 체험 혜택 | 지정 캠페인 흐름에서 CX 증거와 목적 동의 확인 | 다른 상점에 존재하지 않는 혜택을 만들어 내지 않음. 같은 사람·같은 캠페인의 중복 사용 제한 유지 |
| 결제·샘플 배지 | 각 기능의 별도 조건 유지 | CX 본인 확인을 결제 KYC·배지 발급·결제 성공으로 승격하지 않음 |

## 각 기술이 담당하는 경계

- **OmniOne CX:** 모바일 신분증의 실제 제공 결과를 확인하는 서버 경계. 일반 버튼 클릭이나 브라우저 저장값은 증거가 아닙니다. 이번 공통 연결의 대상입니다.
- **OpenDID:** 발급된 자격을 제시하고 현재 유효성을 확인하는 별도 경계. native 독립 구현이 있다고 메인 운영 연동까지 완료된 것은 아닙니다. 실제 CX → holder/CAS 결합 계약과 승인된 bridge 인계가 필요합니다.
- **Sui Testnet:** 기존 승인된 범위의 자격·사용자 위임·실행 증거. 테스트 트랜잭션 성공은 실제 가맹점 혜택 이용이나 결제 완료가 아닙니다.
- **OmniOne Chain:** 승인된 기록 계정으로 사용 결과를 기록하고 receipt를 검증하는 경계. 기존 기록 조회와 새 기록 쓰기를 구분합니다. 현재 recorder 서명 수단이 아직 인계되지 않았습니다.
- **AI:** 장소·콘텐츠를 설명하고 후보를 좁히는 영역. 현재 규칙 기반 응답을 Gemini 실행으로 표시하지 않습니다. 사용자 승인이나 서버 조건 검사를 AI가 대체하지 않습니다.

## 공통 인증의 불변 조건

1. 무료 탐색과 개인 저장 때문에 신분증을 요구하지 않습니다.
2. 현재 서버 세션, 제공자 정책, 동일인 결합, 만료, 취소 상태를 확인합니다.
3. 기존 유효 증거를 재사용하더라도 새로운 행동의 목적 동의는 따로 받습니다.
4. 승인권은 행동 종류·장소·모임·정확한 작성 문맥에 결합하며, 실제 소비점에서 다시 확인합니다.
5. `person`, `adult`, `19+`, `payment KYC`는 서로 대체하지 않습니다.
6. 새 실제 CX 요청은 기존 승인된 총 10개 operation 한도 안에서만 예약합니다. 체인 거래 수 10개라는 뜻이 아니며, 별도 CX 확인과 실제 혜택 실행은 서로 다른 operation을 사용할 수 있습니다. 새 무제한 인증 pool, 예산 초기화, 실행 기간 연장은 없습니다.
7. 검수는 비밀키 없는 로컬 fixture 및 운영의 비변경 UI 확인으로 구분합니다. 본인 휴대폰의 정보 제공 동의는 소유자가 직접 합니다.

## 실제 외부 연결에 남은 입력

[소유자 체크리스트](OWNER_ONLY_NEXT_STEPS_2026-09-29.md)에 본인 동의·제공자 권한·별도 native 작업 인계만 정리합니다.
입력 후 서버 연결·검증이 남으면 Codex가 이어서 수행합니다. 입력 보관 자체를 전체 연동 완료로 처리하지 않습니다.
