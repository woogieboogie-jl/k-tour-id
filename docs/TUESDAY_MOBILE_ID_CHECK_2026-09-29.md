# 화요일 팀원과 함께 확인할 것 — 메인 앱의 실제 CX

2026-09-29 수정본. 배포·검수 결과는 [현재 메인 통합 기록](CX_SUI_MAIN_COMPLETION_2026-09-29.md)을
기준으로 한다. 예전 CX-only Preview 링크와 지갑의 샘플 가입 경로를 혼용하지 않는다.

**확인할 주소:** https://ktour-id.vercel.app/?venueId=mois-0021cd596bc5b2a922ad&review=0

목표는 **K-Tour에서 시작한 요청을 실제 신분증 앱에서 승인하고, 같은 요청의 서버 결과까지 확인하는 것**입니다. QR이 뜨거나 앱이 열리는 것만으로 성공으로 세지 않습니다. 팀원은 자신의 휴대폰에서만 동의하고, 신분증·QR·개인정보를 전달하지 않습니다.

## 먼저 준비할 것

- 팀원: 모바일 운전면허증을 사용할 수 있는 휴대폰. 현재 CX 요청은 `comdl` / `AdultVerify`라 PASS나 다른 신분증을 대신 쓸 수 있다고 보장하지 않습니다.
- 앱: 이미 `OmniOneCX` 요청을 열고 정보 제출에 성공했던 모바일 신분증 앱을 그대로 사용합니다. 다른 팀원은 실제 발급된 모바일 운전면허증을 준비합니다. 임의 APK 설치나 불필요한 신분증 재발급을 먼저 하지 않습니다.
- 검수 담당자: 위 **링크 하나와 기존 접속 코드**를 안전하게 전달합니다. 코드를 팀원이 Vercel에서 직접 찾게 하지 않습니다. 코드 자체는 인증 성공을 대신하지 않습니다.
- 이번 확인은 메인 장소의 **체험 혜택**에서 시작합니다. 지갑의 기존 샘플 가입 / `Simulate approval` 화면은 실제 CX 경로가 아닙니다. 그런 화면이면 승인을 누르지 말고 위 링크로 다시 들어갑니다.

접근 환경의 현재 만료 예정은 9월 30일 23:59:59 KST입니다. 개별 QR·인증 요청은 훨씬 먼저 만료될 수 있으므로 현장에서 새로 만듭니다. 화요일 날짜는 2026년 9월 29일입니다.

## 권장: PC 화면 + 팀원 휴대폰

1. PC에서 위 **메인 앱 링크**를 열고, 장소 미리보기의 **장소 상세 / Place details** → **체험 혜택 보기 / See experience perk**를 누릅니다.
2. 필요한 경우 전달받은 접속 코드를 입력하고 안내에 동의합니다. 이 동의는 아직 신분증 인증 성공이 아닙니다.
3. **모바일 신분증 확인 시작**을 눌러 새 요청을 만듭니다. PC에서는 QR이 표시되고, 모바일 브라우저에서는 앱 링크가 표시됩니다. 예전 오류 요청을 재사용하지 않습니다.
4. 팀원 휴대폰에서 올바른 **모바일 신분증 앱 → QR 촬영**을 선택해 PC의 QR을 촬영합니다. `나의 QR`을 보여주는 메뉴나 별도의 사업자용 검증앱이 아닙니다.
5. 앱에 표시된 서비스와 요청 정보를 확인합니다. 이상하면 중단합니다. 적절하다면 팀원이 직접 동의·정보 보내기와 앱의 본인 인증을 마칩니다.
6. PC의 K-Tour로 돌아와 **결과 확인 / Fetch result**을 누릅니다. 승인 전에 연속으로 누를 필요는 없습니다.
7. 서버가 승인을 확인했는지 살펴봅니다. **오류가 나오면 그 시점에서 멈추고 코드·시각만** 전달합니다. 앱 제출 성공만으로 다음 단계를 완료 처리하지 않습니다.
8. 서버 신원 확인이 실제 통과한 경우에만 패스 발급·제시 → 제안 검토 → 명시적 승인·서명 → Sui 실행 → 장소 복귀를 확인합니다. 검수 담당자는 같은 operation의 거래·서명을 대조합니다. 패스는 OpenDID 제공자 발급 완료 전까지 체험 패스이며, AI는 rule 방식입니다.

휴대폰 한 대라면 3번에 나온 **Mobile ID** 앱 링크를 누릅니다. 앱에서 승인을 마친 후 **원래 브라우저의 원래 탭**으로 돌아와 결과를 확인합니다. 앱 링크 생성과 실제 iOS/Android 왕복은 다른 검증 항목이므로 각각 기록합니다.

## 통과 기준 — 화면과 서버를 함께 확인

| 확인 | 통과 조건 | 담당 |
| --- | --- | --- |
| 앱 연결 | 올바른 앱과 서비스의 요청이 열림 | 팀원 |
| 본인 승인 | 팀원이 자기 기기에서 정보 제출을 승인함 | 팀원 |
| 결과 일치 | 생성한 요청과 조회한 요청이 같고, 공급자의 최종 결과가 확인됨 | 검수 담당자 |
| 동일인·성인 | 안정적인 CI 기반 동일인 결합과 성인 결과 확인. CI가 없는데 요청 ID로 대체하지 않음 | 검수 담당자 |
| 복귀 | 기존 장소와 선택 맥락으로 복귀. 승인 클릭이나 앱 열기만으로 혜택이 사용되지 않음 | 함께 |
| 재조회 | 같은 완료 요청을 다시 조회해도 중복 발급·사용·기록이 생기지 않음 | 검수 담당자 |

**범위:** 이 표는 CX 신원 확인 기준입니다. Sui는 같은 요청의 실제 3거래까지 확인해야 별도로
통과입니다. OmniOne 신규 기록, Google zkLogin, Sumsub 여권 검증, OpenDID 발급까지 자동으로
완료된 것은 아닙니다. 현재 메인은 CX+제한된 Sui Testnet 경로이며 `fulfillment=pending`,
`chain=null`에서 멈추는 것은 실제 매장 혜택 사용/OmniOne 완료가 아니라는 뜻입니다.

## 실패 상황도 두 가지 확인

- **미승인/취소:** 운영자가 이미 한정된 smoke로 검수한 항목입니다. 재현이 필요하면 새 요청을 만든 뒤 승인하지 않거나 취소하고, K-Tour가 성공으로 바뀌지 않는지 확인합니다. 취소도 전체 10개 operation 한도에 포함되므로 현장에서 불필요한 반복 요청을 만들지 않습니다.
- **만료/복귀:** 요청이 만료됐거나 탭을 새로고침한 뒤, 남의 요청이나 예전 승인으로 통과하지 않아야 합니다. 실제 제공자 만료는 시간을 기다려 확인하고, 로컬 fixture 만료 검수와 구별해서 기록합니다.

실패하면 같은 QR을 계속 재사용하지 말고 **시각·오류 코드만 기록**한 뒤 중단합니다. 승인 성공 증빙을 위해 여러 번 불필요하게 개인정보를 제출하지 않습니다.

- `cx_transaction_missing`이 다시 나오면 새 요청의 오류 시각을 전달합니다. 원본 QR/토큰은 보내지 않습니다.
- `cx_subject_unavailable`이면 공급자의 안정적인 동일인 정보 제공 조건을 우리가 추가 확인해야 합니다. 요청 ID를 CI 대신 써서 통과시키지 않습니다.
- `cx_mode_changed`이면 과거 샘플/다른 provider 요청입니다. 기존 건을 취소하고 현재 경로에서 새 요청을 시작합니다.
- `hosted_sui_limit`이면 실행 한도 도달입니다. 새로고침으로 해결하거나 원장을 초기화하지 않습니다.
