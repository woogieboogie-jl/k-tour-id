# Chromium / WebKit 자동 모바일 검수

macOS 14.2의 Playwright WebKit이 페이지 진입 전 SIGBUS로 종료되는 문제와 앱 검수를 분리하기 위해, 지원되는 Ubuntu 24.04 GitHub Actions 실행 경로를 추가했다. 기존 Chromium 성공을 WebKit 성공으로 대체하지 않는다.

## 실행 범위와 경계

- Workflow: `.github/workflows/mobile-compat.yml`.
- 자동 실행은 `integration/autonomous-finish-20260927` 브랜치 push에만 한정된다. 수동 `workflow_dispatch`도 같은 브랜치인지 다시 검사한다. 첫 실행은 해당 브랜치 push로 시작하며, 기본 브랜치에 workflow가 없을 때 GitHub의 수동 실행 UI/API가 제공된다고 가정하지 않는다.
- Ubuntu 24.04, Node.js 24, pnpm 10.8.0, frozen lockfile. 공식 checkout/setup-node/upload-artifact v6 태그를 조회한 전체 commit SHA로 고정했다.
- GitHub token은 `contents: read`뿐이며 checkout 자격증명을 Git 설정에 보존하지 않는다. 환경 secret·Vercel token·공급자 키를 전달하지 않고 배포/체인 실행 명령도 없다.
- 기존 `build:sumsub:local` / `local-sumsub.mjs start`는 `.env` 로드를 거부하고 허용된 기본 OS 환경만 상속한다. 앱 서버는 `127.0.0.1:3139`에만 바인딩한다. 기존 서버가 포트를 사용하면 재사용하지 않고 실패한다.
- 브라우저 자식 프로세스도 별도 환경 허용목록을 사용한다. 기존 모바일 테스트의 실제 KYC 응답 가로채기·공급자 요청 차단·외부 쓰기 금지 검사를 유지한다. 지도/폰트의 허용된 공개 읽기 요청은 가능하다.
- 성공 시 아티팩트를 업로드하지 않는다. 실패 시 해당 실행의 fixture 진단 자료/서버 로그만 보존하며 만료는 3일이다. trace/video는 기존 설정처럼 꺼 둔다. 일부 검사는 성공해도 로컬 스크린샷을 만들지만 성공한 실행에서는 업로드하지 않는다.

## 완료 기준

동일 소스의 고정 Next 빌드에서 `playwright.mobile-compat.config.ts`의 기존 33개 시나리오를 Chromium과 WebKit 각각 실행한다. 재시도·skip 없이 **각 브라우저 33/33**, 총 66개를 통과해야 전체 성공이다. 브라우저별 통과/실패/skip/수집 수는 GitHub job summary에 따로 남긴다. 누락·부분 실행·리포트 오류를 성공으로 세지 않는다.

검사 구성은 지역 흐름 9개, 공개 화면 8개, Sumsub UI fixture 13개, 화면 높이·위치 거절·오프라인 복귀 3개다. UI fixture는 실제 SDK 시작/여권 업로드/webhook·iPhone 카메라·외부 신분증 앱 승인·Google OAuth·체인 서명 증거가 아니다.

## 검증 상태

CI 실행 결과는 아직 이 문서에 성공으로 기록하지 않았다. 최초 실행 URL과 source SHA, Chromium/WebKit의 실제 개수를 확인한 뒤 아래에 추가한다. macOS WebKit의 기존 SIGBUS를 성공으로 덮지 않는다.

로컬 준비 검증: runner의 브랜치/이벤트 제한·환경 허용목록·부분 실행/skip/flaky 거부·브라우저별 결과 집계 **4/4 PASS**, Node 구문 검사와 workflow YAML/범위 검사 PASS, Playwright 수집 **33개 × 2브라우저 = 66개** 확인. 테스트 수집은 브라우저 실행 성공이 아니다.
